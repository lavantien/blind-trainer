# ref_doc layout and regeneration

ref_doc holds the offline grounding snapshots for the 3BLD trainer: `bevy/` (engine docs: release notes, blog, 0.19-to-0.20 migration guide, quick start, docs.rs crate pages for bevy, bevy_ui, bevy_state, bevy_time, bevy_input, bevy_text, bevy_asset, bevy_window, bevy_render, bevy_feathers, bevy_ui_widgets, plus the Feathers text input source), `bld/` (speedsolving wiki raw wikitext for Speffz, List_of_letter_pairs, BLD_Memorization, blddb readmes for both branches), and `vietnamese/` (Wikipedia phonology wikitext, the Kirby JIPA Hanoi Vietnamese paper, the vietnameselanguage/syllable wordlist, tabidots/vn-freqs word frequencies, and the KienTranOMRE/vietnamese-bigram-lm outputs). Every fetched file starts with 3 lines prefixed by `# ` giving source URL, retrieval date, and license, so data consumers skip lines starting with `# `; the one pdf is saved bare with a sidecar `.meta.txt`. Regenerate everything idempotently with `make docs-fetch`, which reruns `scripts/fetch_docs.ps1` and rewrites `MANIFEST.md` with sha-256, byte size, path, and URL per file. The full directory is gitignored local grounding, except this README; see `DATA_PROVENANCE.md` at the repo root for license posture.
