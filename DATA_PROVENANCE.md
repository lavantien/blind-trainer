# data provenance

## ref_ground

ref_ground/ holds TSV dumps converted from two spreadsheet exports of the blddb project (github.com/nbwzx/blddb, GPL-3.0, author Zixing Wang), auto-collected per solver from youtube solve reconstructions by scripts/youtube.py on branch v2. The exports were provided by the repo owner and pinned at dump time:

| source file | sha-256 | retrieval date |
| --- | --- | --- |
| Tommy Cherry's 3BLD algs.xlsx | DE60EFB66F974C123A84004E214D691BA2762B71718A9BF2F764BCA0B33C466A | 2026-10-10 |
| Charlie Eggins's 3BLD algs.xlsx | 3C1BECF9C4ABA50C1945D8513E78F34314B7FDAE767112847ABEDB9F57AA9B68 | 2026-10-10 |

ref_ground/ ships the two blddb workbooks and the TSV data converted from them: the solver sheet directories cherry/ and eggins/, the position maps, simcheck, rows, assigndump, and the pair tables. The conversion tooling and derivation notes stay local and untracked. It is GPL-3.0 derived data, committed under that origin, while the repository code stays MIT.

## derived data

data/vendor and data/ga are locally generated by make gen-data and make ga. They derive from ref_ground/ plus code in this repo, stay gitignored and local, and regenerate on demand.

## ref_doc

ref_doc/ holds offline reference snapshots fetched by make docs-fetch. It stays gitignored local grounding.

The wca group, ref_doc/wca/, was appended manually 2026-10-16 by the a0 task: WCA Regulations notation sections 12e (pyraminx) and 12h (skewb), extracted verbatim from thewca/wca-regulations at commit 415be0875246ba1c946a4d65eaa595f8d14e1a84, Version: April 1, 2026, where the official and draft branch heads are identical. Stored file hashes live in ref_doc/MANIFEST.md, the upstream monolithic file sha256 is 727ee26e1ca2096a38cdfef375ab1ca30a8aad86ab4c30db8ad1b9fa23cd23dc. The current numbering puts pyraminx notation at 12e and skewb notation at 12h, 12a2 is outer block moves and 12a4 rotations for NxN cubes.

## fsrs references

ref_ground/fsrs/ holds FSRS-5 scheduler ground truth captured 2026-10-15 by the f2 task: golden output vectors (reference_vectors.tsv), the pinned corpus and scheduler settings (reference_meta.json), and the generator script (gen_goldens.py). PROVENANCE.md inside that directory records sources and the regeneration recipe.

The golden outputs were generated by running py-fsrs v5.1.3, the last FSRS-5 release (19 weights) of github.com/open-spaced-repetition/py-fsrs, MIT, installed from PyPI as fsrs==5.1.3 and byte-verified against the v5.1.3 tag. ts-fsrs v5.4.2 (github.com/open-spaced-repetition/ts-fsrs, MIT) was cross-checked; its two divergences from py-fsrs v5.1.3 are documented in ref_ground/fsrs/PROVENANCE.md, and the implementation follows py-fsrs v5.1.3. The spec snapshot lives in ref_doc/fsrs/ from the awesome-fsrs wiki page The-Algorithm, which superseded the fsrs4anki wiki URL.

## pack seeds

ref_ground/packs/ holds 15 seed TSVs imported 2026-10-15 as byte-identical copies from the sibling repo cubing-trainer (https://github.com/lavantien/cubing-trainer, MIT, same author) at pinned commit f7ecf2e19a32960d0c0338c528594e0d0c68804f, source path db/seeds/packs/. The rows were originally captured 2026-10-10 by that repo from the public pages recorded per row in each TSV's source_url column (jperm.net, sarah.cubing.net, speedcube.us, cubingapp.com, cubeskills.com, cubing.mikeg.me.uk, speedsolving.com wiki, docs.google.com, and per-row video reconstruction short links). bld_3style_specials.tsv derives from the same GPL-3.0 blddb workbooks as the ref_ground section above and follows its carve-out. registry.json binds each file to event, method, stage, n, and expected rows, ref_ground/packs/PROVENANCE.md records per-file sha-256, ultimate sources, and the origin registry mapping.

## regeneration

Run make docs-fetch for the reference snapshots. The pack TSVs are copies from the pinned cubing-trainer commit, re-copy and sha-256 verify per ref_ground/packs/PROVENANCE.md. The xlsx workbooks are pinned by the sha-256 table above. The TSV conversion and analysis tooling that produced the dumps from the workbooks is kept outside the repository. The FSRS golden vectors regenerate via ref_ground/fsrs/gen_goldens.py per that directory's PROVENANCE.md.
