# data provenance

## ref_ground

ref_ground/ holds TSV dumps converted from two spreadsheet exports of the blddb project (github.com/nbwzx/blddb, GPL-3.0, author Zixing Wang), auto-collected per solver from youtube solve reconstructions by scripts/youtube.py on branch v2. The exports were provided by the repo owner and pinned at dump time:

| source file | sha-256 | retrieval date |
| --- | --- | --- |
| Tommy Cherry's 3BLD algs.xlsx | DE60EFB66F974C123A84004E214D691BA2762B71718A9BF2F764BCA0B33C466A | 2026-10-10 |
| Charlie Eggins's 3BLD algs.xlsx | 3C1BECF9C4ABA50C1945D8513E78F34314B7FDAE767112847ABEDB9F57AA9B68 | 2026-10-10 |

ref_ground/ ships the two blddb workbooks and the TSV data converted from them: the solver sheet directories cherry/ and eggins/, the position maps, simcheck, rows, assigndump, and the pair tables. The conversion tooling and derivation notes stay local and untracked. It is GPL-3.0 derived data, committed under that origin, while the repository code stays MIT.

## derived data

data/vendor and data/ga are locally generated by `python bt.py gen-data` and `python bt.py ga`. They derive from ref_ground/ plus code in this repo, stay gitignored and local, and regenerate on demand.

## ref_doc

ref_doc/ holds offline reference snapshots fetched by `python scripts/fetch_docs.py`. It stays gitignored local grounding.

The wca group, ref_doc/wca/, was appended manually 2026-10-16 by the a0 task: WCA Regulations notation sections 12e (pyraminx) and 12h (skewb), extracted verbatim from thewca/wca-regulations at commit 415be0875246ba1c946a4d65eaa595f8d14e1a84, Version: April 1, 2026, where the official and draft branch heads are identical. Stored file hashes live in ref_doc/MANIFEST.md, the upstream monolithic file sha256 is 727ee26e1ca2096a38cdfef375ab1ca30a8aad86ab4c30db8ad1b9fa23cd23dc. The current numbering puts pyraminx notation at 12e and skewb notation at 12h, 12a2 is outer block moves and 12a4 rotations for NxN cubes.

The jperm group, ref_doc/jperm/, was appended manually 2026-10-16 by the a8 task: pll-algs.js and oll-algs.js are the live case-data scripts served to jperm.net/algs/pll and jperm.net/algs/oll (carrying the standard 3-line header, so stored hashes differ from upstream bytes), and f2l-bestf2l.pdf is J Perm's Best Algorithms for ALL Advanced F2L Cases sheet (updated 2021 August 8) stored bare, resolved from the bit.ly/bestf2l link published on jperm.net/3x3/cfop/f2l to drive.google.com file 1nzAXYUWZJ6H2wIOXaHdWXep3W57tArbR. Stored hashes live in ref_doc/MANIFEST.md. These snapshots are the direct origin of the three cfop_*.tsv seed packs, see the pack seeds section and ref_ground/packs/PROVENANCE.md. jperm.net content carries no explicit license, it is James Straughan's work held as local reference only, same posture as the other web snapshots.

## fsrs references

ref_ground/fsrs/ holds FSRS-5 scheduler ground truth captured 2026-10-15 by the f2 task: golden output vectors (reference_vectors.tsv), the pinned corpus and scheduler settings (reference_meta.json), and the generator script (gen_goldens.py). PROVENANCE.md inside that directory records sources and the regeneration recipe.

The golden outputs were generated by running py-fsrs v5.1.3, the last FSRS-5 release (19 weights) of github.com/open-spaced-repetition/py-fsrs, MIT, installed from PyPI as fsrs==5.1.3 and byte-verified against the v5.1.3 tag. ts-fsrs v5.4.2 (github.com/open-spaced-repetition/ts-fsrs, MIT) was cross-checked; its two divergences from py-fsrs v5.1.3 are documented in ref_ground/fsrs/PROVENANCE.md, and the implementation follows py-fsrs v5.1.3. The spec snapshot lives in ref_doc/fsrs/ from the awesome-fsrs wiki page The-Algorithm, which superseded the fsrs4anki wiki URL.

## pack seeds

ref_ground/packs/ holds 15 seed TSVs imported 2026-10-15 as byte-identical copies from the sibling repo cubing-trainer (https://github.com/lavantien/cubing-trainer, MIT, same author) at pinned commit f7ecf2e19a32960d0c0338c528594e0d0c68804f, source path db/seeds/packs/. The rows were originally captured 2026-10-10 by that repo from the public pages recorded per row in each TSV's source_url column (jperm.net, sarah.cubing.net, speedcube.us, cubingapp.com, cubeskills.com, cubing.mikeg.me.uk, speedsolving.com wiki, docs.google.com, and per-row video reconstruction short links). bld_3style_specials.tsv derives from the same GPL-3.0 blddb workbooks as the ref_ground section above and follows its carve-out. registry.json binds each file to event, method, stage, n, and expected rows, ref_ground/packs/PROVENANCE.md records per-file sha-256, ultimate sources, and the origin registry mapping.

The 3 cfop seed TSVs were authored in this repo on 2026-10-16 from J Perm pages fetched live that day, because cubing-trainer's CFOP tables were unattributed hardcode with no algs for F2L: cfop_pll.tsv (21 rows, first listed alg per case from jperm.net/algs/pll), cfop_oll.tsv (57 rows, first listed alg per case from jperm.net/algs/oll), and cfop_f2l.tsv (164 rows, the 41 basic cases of the archived F2L sheet instantiated for slots fr, fl, br, bl with the fr row verbatim and the other slots mechanically y-conjugated from it). Sources are archived in ref_doc/jperm per the ref_doc section, the per-file selection and derivation rules live in ref_ground/packs/PROVENANCE.md, and registry.json registers each file twice, events 3x3 and oh, method cfop, so oh practice tracks its own cards over the shared files.

M/E slice convention divergence, recorded 2026-10-16, no adapter applied: bld_m2.tsv's M and E tokens follow the speedsolving wiki convention (M acts like L', E acts like D', the convention the pack's source pages assume), while bt-core's slice tables define M as following L and E as following D. Single-direction M and E tokens therefore act inverted between the two readings; M2 and E2 tokens agree under both because a half turn is its own inverse. The divergence is proven by identity tests in bt-verify: under the wiki reading m2.18 delivers DB into the DF buffer exactly as the row labels claim, under the bt-core reading it does not. Rows m2.18, m2.19, m2.20, m2.22 sit on the expected-failure list for this reason (m2.19 fails both readings and carries a label defect). Deliberately not adapted: a convention adapter would churn the pinned canonical row hashes, so the choice between adapting the loader, the engine, or the pack is a user decision, recorded here for that decision.

Known source defects in the packs stay verbatim and are ruled, not fixed: 51 rows across the sq1, megaminx, pyraminx, bigcube, and bld packs sit on the expected-failure table the seed loader carries, each with its recorded reason, and the defect tables plus the negative probes that ruled out repairable explanations live in the data defects section of ref_ground/packs/PROVENANCE.md. bt-verify fails closed on any pack row without a ruling and flags any ruling that stops failing.

## regeneration

Run `python scripts/fetch_docs.py` for the reference snapshots. The pack TSVs are copies from the pinned cubing-trainer commit, re-copy and sha-256 verify per ref_ground/packs/PROVENANCE.md. The xlsx workbooks are pinned by the sha-256 table above. The TSV conversion and analysis tooling that produced the dumps from the workbooks is kept outside the repository. The FSRS golden vectors regenerate via ref_ground/fsrs/gen_goldens.py per that directory's PROVENANCE.md.
