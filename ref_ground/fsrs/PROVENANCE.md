## regeneration

run gen_goldens.py with an isolated python that has fsrs==5.1.3 importable, working directory ref_ground/fsrs:

```
python -I gen_goldens.py
```

it writes reference_vectors.tsv and reference_meta.json. scheduler settings are pinned in reference_meta.json: default parameters, desired_retention 0.9, learning_steps and relearning_steps empty, maximum_interval 36500, fuzzing disabled. empty learning steps make every review schedule through the pure day-granularity interval formula, which is the model bt-data implements. all datetimes are UTC midnights from 2026-01-01, so elapsed days are exact integers. floats are stored as python repr, full double precision.

columns of reference_vectors.tsv: case, step, rating (1 again, 2 hard, 3 good, 4 easy), elapsed_days since the previous review (empty for the first review of a case), retrievability before the review (empty for the first review), stability after, difficulty after, interval_days from due date minus review date.

elapsed semantics: the corpus uses whole days. the reference consumes elapsed as python timedelta.days, which floors: any fractional elapsed floors to whole days before the branch choice and the retrievability input, and negative elapsed floors below zero then clamps to 0, which routes it to the same-day branch. probed against the pinned venv 2026-10-15: gaps 0.5 and -0.5 reproduce the gap 0 outcome exactly, 1.5 reproduces 1.0, 2.9 equals a 2-day gap. the rust port floors identically and pins these probes as tests.

## cross-check notes, ts-fsrs v5.4.2 vs py-fsrs v5.1.3

both agree on: weights count and defaults, DECAY -0.5 and FACTOR 0.9**(1/DECAY)-1, initial stability max(w[g-1], 0.1), initial and next difficulty with linear damping and mean reversion to D0(4) clamped to [1, 10], stability updates consuming the pre-update difficulty, post-lapse stability capped by S / e**(w17*w18), interval round then clamp.

documented divergences, implementation follows py-fsrs v5.1.3 because it is the frozen FSRS-5 release the goldens were generated with:

- same-day short-term stability: ts-fsrs floors the growth factor at 1.0 for grades hard and above, py-fsrs does not, so a same-day hard review scales stability by e**(w17*(2-3+w18)) = about 0.84 rather than staying at 1.0.
- stability clamps: ts-fsrs clamps every stability into [0.01, 36500], py-fsrs only floors the initial stability at 0.1 and leaves later stability values unclamped.

cubing-trainer src/srs/fsrs.c deltas against py-fsrs v5.1.3, recorded so nobody treats the sibling as the reference: it omits the post-lapse min cap, it leaves difficulty unchanged on same-day reviews, and its stability update consumes the post-update difficulty. its weight vector and all other formulas match.
