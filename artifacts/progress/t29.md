## Blocker for the hub: bt.py raylib wiring (L0-owned file, patch ready)

lane-15 needs 4 bt.py amendments before any tests/unit/app suite can link.
bt.py is outside my scope so I did not touch it. Exact request:

1. compile includes: add `vendor/raylib/src` and
   `vendor/raylib/src/external/glfw/include` to the include set of every c
   compile (same slot as SYSTEM_INCLUDE_DIRS). src/app/*.c include <raylib.h>.
   Keys already exist in config hub build.raylib_build.include_dirs.
2. link: link `build/vendor/raylib.lib` plus build.raylib_build.system_libs
   (opengl32 gdi32 user32 shell32 winmm) into every exe. The static lib is
   inert when unreferenced so core/scheme/data/ga/puzzles exes are unchanged.
   Needed because every suite exe links all src objects and src/app will own
   raylib-calling units (ui.c, net draw, main.c, probe tests).
3. exclude `src/app/main.c` from the default src_objects link set for tool
   exes and suite exes (it defines main(), collides with generated test mains
   and tool main.c). Same pattern as the existing main.c exclusion for tool
   suites.
4. add the app exe link: build/bin/bt-app.exe = all src objects minus
   src/app/main.c + src/app/main.obj + raylib.lib + system libs. L20 drivers
   and the future run target drive this exe.

No flag additions anywhere, all values read from the config hub.
