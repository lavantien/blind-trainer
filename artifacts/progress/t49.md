# t49 lane-views-fonts

Task: fix the production font-size defect adv-24a pinned. Three views passed raw theme rem values as pixel font sizes while their line advances multiply by theme->root_rem (20.0), so text drew at 0.8 to 3.4 px.

## Origin, corrected after the adversarial round

The raw rem sites are not a regression introduced after a working state: they date to the original port commits themselves (solve.c at 9bdce5c, algs mod.c at a1d4113, case_drill_view.c at eb1d60b), with the theme already rem-based. No later commit removed a multiplier. These three views never drew visible text before f53951f; the earlier readable gallery was the Rust-era set. The earlier framing of this log called it a regression, which was wrong. The fix description below stands unchanged.

## Adversarial round (adv-fonts-a zero defects, adv-fonts-b four findings, ea74735 and d635363)

1. Dead query filter, fixed. bt_view_algs_read_query had no production caller and the algs update read GetCharPressed, a queue the loop-level bt_app_poll_input drains into the frame input before any update runs, so typed chars never reached the query and algs-search showed 818 of 818. Wiring: the update now reads chars from bt_app_frame_input (both the query branch and the override draft branch), and bt_view_algs_frame appends printable chars to app->query and pops on backspace when the query is focused without a draft case, matching the Rust observable where the query is an editable text filtered live. The slash focus key never seeds the query. Two further delivery defects surfaced while proving this end to end: the usage driver posted an explicit WM_CHAR next to a keydown that raylib already turns into a char, so press_char delivered 'b' twice and the filter matched nothing, proven by playground/l49/probe_input.c (keydown alone one char, keydown plus WM_CHAR two chars); and the draft branch double-popped backspace (update's IsKeyPressed poll plus the same key polled into frame). The driver now posts only the keydown, and the draft branch reads only chars. Red-first pin: views_algs_test typed_chars_filter_the_list_through_the_production_frame drives frame and the update-with-frame-input seam, asserts the query narrows from 818, the count line changes, and backspace restores the full list. Fresh algs-search.png reads "38 of 818 cases match" with the B-prefix rows listed and the selection moved, so README caption 15 holds as written.
2. Multiline collision, fixed. parts.splits joins 3 lines with newlines but the rail drew them as one line advance, so "total 5.2s" painted over the hint at y388 (adv-fonts-b crop solve-review-collision.png). Per the Rust layout, where each zone is a text node whose embedded newlines stack inside the node, solve.c now draws the splits and broken blocks through draw_text_block, one line per advance, and the inter-zone gaps stay once per block. Red-first pin: view_draw_b solve_review_hint_draws_clear_of_the_splits_block renders the review phase and asserts the bottom text band is a single small line separated from the band above by at least 20 blank rows. Fresh solve-review.png bands: phase 94-103, result 310-334, splits 342-356, 368-382, 394-408, hint 470-480, disjoint.
3. Gallery determinism, fixed. The drill net pulse lerps on wall clock, so the 4 drill shots differed 3158 to 3682 px between tours. The smoke tour freezes the shared net (drivers.c arm_smoke_resources sets net.frozen = 1, factor pinned to 1.0 in net.c); the usage tour now sets the same freeze in usage_run. Only the drill legs arm net highlights (drill.c 400-403; solve clears targets at solve.c 441-444, memo never sets them), so the freeze touches only those legs. Red: playground/l49/determinism.ps1 two tours, 4 drill shots differ (determinism_red.log).
