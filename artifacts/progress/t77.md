- The coverage build uses its own obj base build/obj-cov and bin dir build/bin-cov with its own link stamp, because compile_stage prunes sibling hash roots under build/obj and the plain build/bin exes are locked by concurrent lanes.
- Run 1 failure was mine: adding the coverage section to config/config.json grew it from 7474 to 8274 bytes, past ga_run_lib_test's 8191-byte fread cap, so its patched scratch config came out invalid json and the suite reported the config offender instead of the freq offender. Fixed by reading the file size first with a loud cap check and 32768-byte buffers.
- Run 2 failures were the app lane's uncommitted WIP racing the full tree instrumented build: all four failing suites' sources sat inside their dirty set and their own newer plain rebuild passed three of the four. The coverage target failed loud on a red tree, which is correct. Landed run 3 through playground/t77cov/run_when_app_clean.py, which waits for a clean src/app plus tests/unit/app before running.
- The ci badge lane landed tests/python/test_ci_badge.py pinning coverage.svg at the placeholder 0.0% mid flight; the pin refresh rides in the same commit as the measured badge, matching the alg-coverage and ci.svg pin convention.
