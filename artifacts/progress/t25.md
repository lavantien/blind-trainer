## Fix pass: adversarial round

Finding 1, heap overread on truncated trailing utf8. Root cause: the decoder
consumed the NUL terminator as payload and returned a width that walked the
parse and is_nfc loops past the allocation. Fix: one well-formed decoder in
src/ga/features.c rejects truncated, overlong, surrogate, and out of range
sequences and never reads past the terminator; bt_ga_utf8_valid drops its
now redundant walk level checks and delegates to the decoder. Red first:
features.parse_rejects_malformed_utf8_sequences and
inventory.utf8_checks_reject_malformed_sequences failed on the is_nfc rows
(is_nfc accepted overlong, surrogate, and out of range input), and the ASAN
scratch build playground/l5fix/utf8_overread.c over a heap copy of "ma\xc3"
reported heap-buffer-overflow READ in bt_ga_parse against the old decoder
and a clean rejection against the fixed one. Rust parse and is_nfc take &str
so invalid utf8 never reaches them: the aligned observable is rejection,
matching the pinned expectations. Verification: python bt.py test-unit ga
10 passed 0 failed, fmt clean, lint ga failures all pre existing lowercase
float suffix style in untouched lines (ga.c:72, features.c:611,
features_test.c:232 at HEAD).

Finding 3, strict aliasing overwrite in pair parsing. Root cause:
bt_ga_dist_parse_pairs cast a uint32_t field address to uint64_t and let
bt_ga_dist_integer write 8 bytes through it, clobbering the adjacent field:
json from 4294967296 loaded as from 0 to 1 while serde rejects the u32
overflow. Fix: bt_ga_dist_u32 parses into a uint64_t temporary, range
checks against UINT32_MAX, and rejects the load on overflow, no aliasing
cast. Red first: dist.pair_rows_reject_values_over_u32 failed because the
over range rows loaded. Verification: python bt.py test-unit ga 10 passed
0 failed, fmt clean, lint ga unchanged 8 pre existing failures, dist.c
clean.

Finding 4, degenerate input divergences, four alignments:
parse_u64 now accepts a single leading plus and rejects u64 overflow
instead of wrapping, matching u64::from_str; bt_ga_trim now trims the
unicode whitespace set through the new common bt_space_len classifier
(the table moved out of puzzles geometry.c into src/common/space.c so ga
and puzzles share one copy, puzzles calls it directly), matching
str::trim which removes NBSP and the rest of the White_Space set;
bt_ga_random_individual shuffles with the count down loop so pool_size 0
draws nothing, matching the Rust empty (1..len).rev() range;
bt_ga_dist_parse_cases rejects orbit strings over 15 bytes and letters
strings over 7 bytes, one byte short of each fixed field for the NUL,
instead of snprintf truncation (Rust strings are unbounded, rejection is
the chosen C bound and it is pinned at exactly the field cap edge).
Red first: inventory_more.loaders_trim_unicode_whitespace_and_parse_u64
like_rust aborted on the plus row, ga.run_survives_an_empty_pool crashed
on the wild scratch index, and dist.case_rows_reject_strings_past_the
field_caps failed on the truncating rows. Verification: python bt.py
test-unit ga 10 passed 0 failed, test-unit puzzles 9 passed 0 failed,
scoped fmt clean on every touched file, lint ga back to the 8 pre
existing failures with space.c clean, lint puzzles 0 failed.

Finding 2, missing ga fuzz surface. tests/fuzz/ga.h carries the
LLVMFuzzerTestOneInput body driving bt_ga_parse over a NUL terminated
copy of the raw bytes plus bt_ga_load_wordlist,
bt_ga_load_syllable_frequencies, and bt_ga_load_freq_data over the raw
bytes written to artifacts/fuzz/ga-input.bin, and tests/unit/ga/
fuzz_ga_test.c drives the plainloop convention (corpus replay under
tests/fuzz/corpus/ga plus seeded generation under fuzz.runs, fuzz.secs,
and fuzz.seed from the hub). The suite stem fuzz_ga_test matches the
fuzz_ filter so bt.py fuzz picks it up. fuzzkill_ga_test.c keeps its
name: fuzzkill is the repo wide pin suite convention mirroring crates/
bt-ga/tests/fuzzkill_ga.rs, it never claimed to be a fuzz surface. The
seed corpus (16 inputs covering the truncated, overlong, surrogate, out
of range, wordlist, freq, and json classes) is generated into both
tests/fuzz/corpus/ga and fuzz/fuzz/corpus/ga by playground/l5fix/
make_corpus.py because corpus trees are untracked by convention and
vendor.py resyncs from the fuzz tree. The truncated tail class is
demonstrated: with the corpus emptied the generated loop alone ran 4649
inputs and fed 491 inputs ending in a lead byte to the parse surface,
and the suite asserts the counter is nonzero every run. Verification:
python bt.py test-unit ga 11 passed 0 failed, scoped fmt clean, python
bt.py fuzz currently blocked by the in flight visual-diff lane
(raylib.h missing in tools/visual-diff builds), ga area compiles clean
inside test-unit ga.

Adversary B extension of finding 1, folded in. bt_ga_utf8_valid was
also unsafe on the old decoder: it read p[1] through p[3] unconditionally
once a lead byte matched a width class, so an exact size heap buffer
holding a bare lead plus the NUL overread at decode time before the walk
level checks could run. The landed factored decoder already guards every
continuation read, so the same fix covers it. Proof: playground/l5fix/
utf8_overread.c drives parse, utf8_valid, and is_nfc each over exact
size heap copies in separate processes, the pre fix decoder (b3092f2^)
reports heap-buffer-overflow for parse on "ma\xc3", utf8_valid on
"\xe1", and is_nfc on "\xf0\x9f", while utf8_valid on "\xe1\xba"
already rejected in bounds even before the fix, and the current tree
prints ok=0 with exit 0 for all four cases. The 4 byte overlong of
U+1EA3 ("\xf0\x81\xba\xa3"), which the old parse accepted as a normal
base vowel with the hoi tone, is pinned in both malformed rows.
