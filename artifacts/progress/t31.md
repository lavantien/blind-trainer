synth params hash root cause: the common bt_json_serialize prints floats in shortest-%g form, 2.0 becomes 2 and 1e-7 becomes 1e-07, and that format is pinned by tests/unit/common/json_test.c serialize_is("1e-7", "1e-07"), so the shared serializer is deliberately not serde_json parity. serde_json::to_string prints 2.0 with the fraction and 1e-7 without the padding, and the Rust hash preimage is that serialization of the synth section plus a NUL plus the generator. Integers were already canonical in the shared code, only floats diverged. Fix: gendata owns its serde-parity compact serializer (serde_value and helpers in tools/gendata/lib.c), the same ownership pattern as bt_gd_json_pretty in model.c, and bt_gd_synth_params_sha256 now hashes through it. This also restores the skip logic: the tool now computes the same hash the golden manifest carries, so an unchanged config and corpus skips regeneration exactly like the Rust tool. Known corner, unreachable for current configs: floats at or above 1e16 with a multi-digit mantissa print exponent-first instead of ryu's decimal form.
