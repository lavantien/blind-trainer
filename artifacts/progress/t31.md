build_test crash, root cause and fix: bt_corpus_from_rows moves the caller's pointer (out->rows = rows) and bt_corpus_free frees that array plus each row's fields, so passing a stack array is an invalid free of stack memory, detected as 0xC0000374 with no output. Hunt path: per-test traced main pinned the crash inside the first test, then an ASan build (trace_build.py asan, needs the LLVM lib/clang/*/lib/windows runtime dir on PATH, ASAN_OPTIONS=detect_odr_violation=0 for empty-literal global noise) reported attempting free on address not malloc-ed pointing exactly at the rows stack slot. The suite now heap-copies the row array before from_rows (corpus_of helper), matching the landed idiom in tests/unit/app/view_draw_test.c single_pair_corpus. All 9 tests pass and the ASan run is clean.
