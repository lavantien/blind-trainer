# t26 lane L8 jobwrap and sleeper port

## plan

Port tools/bt-jobwrap and tools/bt-sleeper to C23 under TDD, expected values only from the
Rust test bodies in tools/bt-jobwrap/src/lib.rs, tools/bt-jobwrap/tests/ceiling.rs, and
tools/bt-sleeper/src/lib.rs. Two commits: sleeper first, then jobwrap with its ceiling
suite, because a tools dir without main.c breaks the bin link stage so the jobwrap units
land as one atomic feature.

Design notes:

- jobwrap calls the real windows.h job object APIs directly (CreateJobObjectW,
  SetInformationJobObject with JOBOBJECT_EXTENDED_LIMIT_INFORMATION,
  JOB_OBJECT_LIMIT_PROCESS_MEMORY plus JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE, suspended
  CreateProcessW, AssignProcessToJobObject, ResumeThread, wait, exit propagation, close on
  every path). The hand-declared FFI of tools/bt-jobwrap/src/ffi.rs becomes
  tools/jobwrap/ffi.c behind real headers. No POSIX branch: the build target is
  x86_64-pc-windows-msvc only and unverifiable code cannot pass the chain.
- ceiling tests live in tests/unit/tools/jobwrap_ceiling_test.c (the file map path
  tools/bt-jobwrap/ceiling_test.c cannot run there, suite mains are generated only under
  tests/unit). They spawn the real build/bin exes with a per-test BT_CONFIG override,
  which needs a local env-block spawn helper because tests/unit/tools/spawn_util.h has no
  environment parameter and is shared with the mutate and gate suites.
- sleeper keeps the plain <secs> behavior and gains the selftest alloc and hold modes the
  lane brief requires; their parse expectations are ported from the jobwrap Rust test
  parses_selftest_modes because bt-sleeper has no such Rust tests.
- error strings, exit codes (payload code, 2 usage, 3 failure), stderr lines, and the
  pidfile anchor semantics (name alphabet, "<pid> <ticks>" dotnet utc ticks, removal on
  exit) mirror the Rust bodies exactly.
