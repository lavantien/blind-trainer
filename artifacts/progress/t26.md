# t26 lane L8 jobwrap and sleeper port

## plan

Port tools/bt-jobwrap and tools/bt-sleeper to C23 under TDD, expected values only from the
Rust test bodies in tools/bt-jobwrap/src/lib.rs, tools/bt-jobwrap/tests/ceiling.rs, and
tools/bt-sleeper/src/lib.rs. Two commits: sleeper first, then jobwrap with its ceiling
suite, because a tools dir without main.c breaks the bin link stage so the jobwrap units
land as one atomic feature.

Design notes:

- jobwrap calls the real windows.h job object APIs directly (CreateJobObjectW,
  SetInformationJobObject with JOBOBJECT_EXTENDED_LIMIT_INFORMATION,
  JOB_OBJECT_LIMIT_PROCESS_MEMORY plus JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE, suspended
  CreateProcessW, AssignProcessToJobObject, ResumeThread, wait, exit propagation, close on
  every path). The hand-declared FFI of tools/bt-jobwrap/src/ffi.rs becomes
  tools/jobwrap/ffi.c behind real headers. No POSIX branch: the build target is
  x86_64-pc-windows-msvc only and unverifiable code cannot pass the chain.
- ceiling tests live in tests/unit/tools/jobwrap_ceiling_test.c (the file map path
  tools/bt-jobwrap/ceiling_test.c cannot run there, suite mains are generated only under
  tests/unit). They spawn the real build/bin exes with a per-test BT_CONFIG override,
  which needs a local env-block spawn helper because tests/unit/tools/spawn_util.h has no
  environment parameter and is shared with the mutate and gate suites.
- sleeper keeps the plain <secs> behavior and gains the selftest alloc and hold modes the
  lane brief requires; their parse expectations are ported from the jobwrap Rust test
  parses_selftest_modes because bt-sleeper has no such Rust tests.
- error strings, exit codes (payload code, 2 usage, 3 failure), stderr lines, and the
  pidfile anchor semantics (name alphabet, "<pid> <ticks>" dotnet utc ticks, removal on
  exit) mirror the Rust bodies exactly.

## adversarial fix round

- 2026-10-27 the two-reviewer attack confirmed 9 findings, all fixed tests-first.
- 1 make_dirs called _mkdir on every prefix including the drive root C:, which fails
  non-EEXIST, so an absolute pid_dir broke wrap mode where Rust create_dir_all accepted
  it. Fixed: each component is created only when missing (GetFileAttributes check), and
  the ceiling suite gained missing_absolute_pid_dir_is_created_by_the_wrapper, red first
  (wrapper exited 3, pidfile never appeared) then green.
- 2 and 6 main read ANSI argv and re-widened it as UTF-8, which mangled non-ASCII payload
  arguments (café became 5 characters, 愛 became ?) where the Rust encode_utf16 chain is
  lossless, and the port had invented payload caps (64 args, 8192 per arg, 8192 line)
  that Rust does not have. Fixed: wmain plus wide argv end to end (parse, quote, command
  line, spawn all wide, ffi takes the wide line and copies it mutable for
  CreateProcessW), the payload is a borrowed pointer slice with no count cap, and the only
  budget left is the real CreateProcessW 32767-character command line in
  BT_JOBWRAP_CMDLINE_MAX. New pins: 109-argument payload parses, an over-budget command
  line is rejected, wide quote and command line pass café and 愛 through with exact
  lengths and codepoints, and the ceiling suite wraps pwsh -File with a BOM script that
  exits 0 only when the café argument arrives as 4 characters.
- 3 the error 87 record in this log and in playground/l8/probe.c was wrong: the wide
  environment block was rejected only because CREATE_UNICODE_ENVIRONMENT was missing, not
  a box defect. Re-probed with the flag: the sorted wide block and the minimal block both
  spawn cleanly, so the probe now sets the flag and both routes are proven. The ceiling
  spawn keeps the _putenv plus inherit route as observable parity: Rust Command::env
  reaches the same child-visible state (BT_CONFIG overridden, every other inherited
  variable present) through its own Unicode block with the flag, and the inherit route
  needs no block building in the test.
- 4 u64 selftest numbers now accept one leading plus exactly like Rust
  str::parse::<u64>, pinned in both suites (+640 parses, ++640 still rejected).
- 5 Sleep capped every hold at about 71.6 minutes where Rust slept the full duration.
  Fixed: holds loop in 1000 ms chunks until the whole total elapses, with u64 saturation
  at ULLONG_MAX. bt_sleeper_sleep_ms(total, chunk) is public and pinned
  (450 ms across 100 ms chunks covers the full total, 0 returns immediately), the spawned

## argv contract for bt.py wiring

- jobwrap.exe [--anchor NAME] -- <command> <args...>: wraps the payload under a job with
  the per-process memory ceiling from config job.per_process_bytes via BT_CONFIG, writes
  <memguard.pid_dir>/<NAME>-<pid>.pid holding "<pid> <dotnet utc start ticks>" and removes
  it on exit, propagates the payload exit code, exits 2 on usage errors printing the usage
  block, exits 3 on config or spawn failures.
- jobwrap.exe --selftest-alloc-mb <N>, N >= 1: sacrificial allocator payload.
- jobwrap.exe --selftest-hold-secs <N>, N >= 0: sacrificial hold payload.
- sleeper.exe <secs>: fractional non-negative seconds, exit 0, exit 2 on usage errors.
- sleeper.exe --selftest-alloc-mb <N> | --selftest-hold-secs <N>: same semantics as the
  jobwrap selftest modes for the memguard matcher.
