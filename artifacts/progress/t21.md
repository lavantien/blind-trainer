  bt_fuzz_seed_from, bt_fuzz_within_bounds, the fuzz_bounds loop, corpus

## Step 2: bt.py target wiring

- fuzz: builds, then runs every fuzz_*_test suite exe through the same
  runner as test, exit codes propagate. The docstring records that harness
  bodies keep the early-return and the exit-at-bound semantics apply only
  under a libFuzzer driver.
- mutants [area...]: areas core, scheme, data, puzzles, ga, app, default the
  ones with a src/<area> directory. tools/mutate/main.c accepts exactly one
  --exe value per invocation, so the target runs one mutate invocation per
  (area, suite) pair, each with its own ledger
  artifacts/mutants/ledger-<suite>.tsv, because the ledger upsert resets rows
  whose test_exe differs and a shared ledger would rerun and overwrite
  verdicts. Each ledger is reported to artifacts/mutants/outcomes-<suite>.json,
  then mutants-gate merge folds them into artifacts/mutants/outcomes.json.
  The killer set excludes fuzz_ suites: they run the full plainloop budget
  per mutant and cargo-mutants never ran fuzz targets either, only unit and
  integration tests. --exe takes the bare suite name, for example
  core_alg_test, per the engine's gen main object lookup.
- mutants-gate: builds then runs mutants-gate.exe over
  artifacts/mutants/outcomes.json and config/allowlist.tsv, exits propagate.
- mutants-gate-selftest: builds then runs mutants-gate.exe selftest.
- build_tool_exe generalized into build_suites plus ensure_tool_exes, policy
  and policy-selftest now share tool_run. bt.py stays under the 1000 line
  cap, several airy literals were compacted with no behavior change.
- gen_migrations freshness: build and check first regenerate the embedded
  pair into a throwaway tree built from the real script plus db/migrations,
  format the generated pair with the committed .clang-format, compare bytes
  against the committed src/data/migrations_embedded.c and .h, and fail
  naming python scripts/gen_migrations.py and bt.py fmt-fix when they drift.
  Nothing regenerates in place during a build. The probe pre-creates src/data
  because the generator assumes it exists, and it formats before comparing
  because the committed copy is the formatted form: the raw generator emits
  1500 character lines that the repo style wraps after the assignment, the
  lane 3a committed copy already matched formatted output byte for byte.
- python pins: test_bt_targets pins the 4 new names, test_bt_mutants pins
  mutants_plan pairing, area rejection, and the area tuple, test_bt_migrations
  pins fresh, tampered, missing, and the command named in the error.
- Smoke: fuzz 4 passed 0 failed, mutants-gate-selftest exit 0, mutate run
  accepted the exact argv shape the target builds, a full cube.c ledger
  against core_cube_test feeds report, merge, and the gate target.
