# t46 release-verify port

## scope

Port tools/bt-release-verify (rust) to C23 at tools/release-verify. Wire bt.py targets release-verify, release-verify-selftest, and dist mirroring the Makefile contract. TDD: the rust unit tests were transcribed as failing C tests first, expected values taken only from the rust test bodies.

## emitter ruling

Chose semantic compare, no json emitter change. The tool writes no report.json artifact, its outputs are stdout ok/fail lines and exit codes only, so the frozen-surface exception for a pretty declaration-order bt_json_serialize mode is not needed. src/common/json is untouched.

## substitutions under the detached mutation host

- release-verify and release-verify-selftest build through build_scope(tools, only=release_verify) and run the exe directly with the same argv and child_env that tool_run/ensure_tool_exes would use, because ensure_tool_exes does a full-tree link that can rewrite build/bin/mutate.exe held by the mutation host.
- dist builds only the app area (build_scope app) instead of the Makefile full build target, then stages bt-app.exe as build/bin/blind-trainer.exe (the rust build emitted the app under that name directly) and runs scripts/dist.py plus release-verify. Same argv and env as the Makefile flow.
- policy gate ran as scoped policy build plus direct policy.exe calls (selftest then scan) with identical argv and env.

## structure

tools/release-verify: main.c (wmain entry, trace from config), lib.c (config parse, stage pipeline, run), zip.c (staging set, zip check, extract, crc32), inflate.c (raw and zlib inflate, deflate tables string-encoded and parsed once to satisfy the literal policy), png.c (signature, chunk crc, ihdr dims, idat zlib decode, unfilter), exec.c (env scrub, child spec, spawn with pipes, timeout kill tree). Suites: tests/unit/tools/release_verify_test.c (lib.rs bodies), release_verify_zip_test.c (zipcheck.rs bodies), release_verify_exec_test.c (exec.rs bodies), shared release_verify_test_util.h (scratch dirs, stored-zip writer, gray png writer).

## decisions

- BT_RV_LATEST_USER_VERSION 3 pins db/migrations count, the rust bt_data::db::LATEST_USER_VERSION equivalent. A test cross-checks the constant against the live migration file count so drift fails the suite.
- The db file name fallback constant lives in the tool because tool_deps keeps release-verify empty, matching the rust crate constant blind-trainer.db.
- zip names normalize backslashes, strip the staging folder prefix, skip trailing slash entries, reject duplicate normalized names and .. segments, exactly as zipcheck.rs.
- png verification is a full decode: signature, per-chunk crc32, ihdr dims, zlib idat inflate with adler32, scanline unfilter, exact size. Interlaced pngs are rejected as undecodable, the app never writes them.
- typos.toml gained paeth = paeth, the png predictor name.
